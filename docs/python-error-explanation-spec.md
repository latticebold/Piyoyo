# Python実行エラーの日本語説明仕様

## 目的

Pythonが出したエラーを、初心者が次にコードのどこを確認すればよいか分かる短い日本語で表示する。
説明は例外の種類とエラー本文から確認できる事実に限る。判定できない原因を推測して断定しない。
この文書を実装とテストの基準とする。対応する説明生成は `src/runners/pythonErrorExplainer.js` に実装している。

## 表示と入力

- 通常表示は `7 行目: リストと文字列を足そうとしています。` のように、場所と原因を短く示す。
- 詳細ルールに一致した場合は、エラー本文が示す名前・型・演算・個数・値をできるだけ含める。必要な場合だけ、次に確認する箇所をもう1文で示す。
- 行番号を確認できない場合は、行番号なしで原因を示す。実行対象以外のユーザーファイルならワークスペース相対パスも示す。
- 説明の入力は、終了コード、標準エラー出力、起動エラー、タイムアウト、実行対象ファイルのパス、ワークスペースのフォルダー群とする。Pythonがstderrに書いた内容は改変せず保持する。
- 元のエラーとトレースバックは、詳細設定 `piyoyo.advanced.showOriginalErrors` を有効にした場合に確認できる。通常表示に英語のエラー本文を混ぜない。

## 判定の順序

1. タイムアウトとPythonの起動失敗は、それぞれ専用の説明を出す。
2. 終了コードが `0` なら実行エラーの説明は出さない。stderrだけに注意事項がある場合は、注意事項が出たことを示す。
3. Pythonのエラー出力から、最後にプログラムを停止させた例外の種類と本文を取り出す。連鎖した例外では最後の例外を採用する。`Error` や `Exception` で終わらない例外名や、本文のない例外名も扱う。
4. 例外の種類と本文が登録済みの詳細ルールに一致すれば、その説明を出す。
5. 詳細ルールに一致しなければ、例外の種類に応じた控えめな説明を出す。例外自体を判定できなければ、異常終了を伝える。

例外名は、トレースバックまたは構文エラーの表示に結び付いた行からだけ取り出す。stderr中の任意の `Name: ...` という行を例外とは扱わない。
行番号は最後の例外に属するトレースバックから得る。最も深いフレームが実行対象ファイルなら `7 行目`、ワークスペース内の別ファイルなら `lib/helper.py の 7 行目` と表示する。例外が外部ライブラリ内で起きた場合は、利用者側の呼び出し行を `7 行目から呼び出した処理で` のように示し、その行をエラーの発生箇所と断定しない。利用者のファイルに対応するフレームがなければ行番号を付けない。
構文エラーは通常の実行時トレースバックと形式が異なるため、`File ..., line N` の形式も扱う。
例外グループなど、最後の例外を単純な1行として判定できない形式は異常終了の一般説明へ戻す。

## `TypeError` の `+` に関する詳細ルール

次のいずれかのPythonのエラー本文と全体が一致し、左右の型名を既知の型として読める場合にだけ、`<左の型>と<右の型>を足そうとしています。` と表示する。

- `can only concatenate list (not "str") to list` のような形式。前後にある基準の型名が同じことを確認する。
- `unsupported operand type(s) for +: 'list' and 'str'` のような形式。`type` と `type(s)` の表記差を許容する。

左右の順番はPythonのエラー本文にある演算対象の順番を保つ。型名は固定の対応表で日本語にする。
初期の対応表は `str` →「文字列」、`list` →「リスト」、`int`・`float`・`complex` →「数値」、`bool` →「真偽値」、`tuple` →「タプル」、`dict` →「辞書」、`set` →「集合」、`bytes` →「バイト列」、`NoneType` →「None」とする。
未知の型名、別の演算子、形式が異なる本文では、推測せず `TypeError` の一般説明を使う。

| Pythonコード | 日本語の原因 |
| --- | --- |
| `[0] + "str"` | リストと文字列を足そうとしています。 |
| `"str" + [0]` | 文字列とリストを足そうとしています。 |
| `"str" + 1` | 文字列と数値を足そうとしています。 |
| `1 + "str"` | 数値と文字列を足そうとしています。 |
| `[0] + 1` | リストと数値を足そうとしています。 |
| `1 + [0]` | 数値とリストを足そうとしています。 |

上表の例外本文はCPython 3.12.13で確認した。実行環境によって本文が異なる場合は、確認済みの形式を追加するまで一般説明を使う。

`+` 以外の演算、関数の引数、添字などは、それぞれ確認済みのエラー形式と日本語の説明を追加してから詳細ルールに登録する。
型名だけから、どの値へ変換すべきかまでは決めない。
詳細ルールを追加するときは、対象の例外の種類、エラー本文の全体に一致する形式、抽出できる情報、日本語の説明、似ているが一致させない例をセットで記録する。
原因の判定にトレースバック中のソースコード文字列を使わない。ソースコードは改行や複数の演算を含むため、エラー本文で確認できない原因を補う根拠にはしない。

## よくあるエラーの詳細ルール

`+` の型違いに加え、次の形式を優先して登録する。`N` は名前、`T` は型名、`M` はモジュール名、`R` はエラー本文に含まれる値の表現、`k` は個数を表す。形式は例外の種類と本文全体で照合する。

| 例外とエラー本文の形式 | 日本語の表示例 |
| --- | --- |
| `NameError: name 'N' is not defined` | 名前「N」が定義されていません。 |
| `UnboundLocalError: cannot access local variable 'N' where it is not associated with a value` | 関数内の名前「N」を、値が入る前に使おうとしています。 |
| `AttributeError: 'T' object has no attribute 'N'` | Tに「N」という属性はありません。 |
| `ModuleNotFoundError: No module named 'M'` | モジュール「M」が見つかりません。 |
| `ImportError: cannot import name 'N' from 'M'`（後述の場所情報を許容） | モジュール「M」から「N」を読み込めません。 |
| `IndexError: list index out of range` | リストの添字が範囲外です。 |
| `IndexError: string index out of range` | 文字列の添字が範囲外です。 |
| `IndexError: tuple index out of range` | タプルの添字が範囲外です。 |
| `KeyError: R`（安全に表示できる短いキーのみ） | Rというキーが見つかりません。 |
| `ZeroDivisionError: division by zero` | 0で割ろうとしています。 |
| `ValueError: invalid literal for int() with base 10: R` | Rは10進整数に変換できません。 |
| `ValueError: could not convert string to float: R` | Rは浮動小数点数に変換できません。 |
| `TypeError: 'T' object is not subscriptable` | Tの値に添字を指定しようとしています。 |
| `TypeError: 'T' object is not callable` | Tの値を関数のように呼び出そうとしています。 |
| `TypeError: len() takes exactly one argument (k given)` | `len()`には引数が1個必要ですが、k個渡されています。 |
| `TypeError: can't multiply sequence by non-int of type 'T'` | 繰り返す回数には整数が必要ですが、Tを指定しています。 |
| `SyntaxError: expected ':'` | コロン `:` が必要です。 |
| `SyntaxError: unterminated string literal (detected at line k)` | 文字列を囲む引用符が閉じられていません。 |
| `EOFError: EOF when reading a line` | `input()`が読み込む前に入力が終わりました。 |

表の `T` は前節の固定対応表で日本語にする。`N` は1〜64文字のPython識別子、`M` は合計128文字以内で各部分が同じ条件を満たすドット区切りの名前、`k` は9桁以内の0以上の整数に限る。条件を満たさない名前や個数は表示せず、対象を特定しない説明へ戻す。
`ImportError` の後ろには、接尾辞なし、文字列 ` (unknown location)`、または括弧と改行を含まない260文字以内のパスを ` (パス)` として続ける形式だけを許す。場所情報は日本語の説明へ引用しない。
値 `R` はPythonの `repr` として受け取るが、評価してオブジェクトに戻さない。表示するのは、両端が同じ引用符で囲まれ、内部に引用符・バックスラッシュ・改行・制御文字がない40文字以内の文字列、または12桁以内の符号付き整数だけとする。文字列は `「abc」`、整数は `2` のように表示する。条件外なら値を伏せ、「整数に変換できません」「キーが見つかりません」などの説明にする。
画面には抽出した文字列をテキストとして置き、HTMLとして解釈させない。エラー本文にない添字の数値、リストの長さ、利用者が意図した修正方法は補わない。
Pythonの実装や版で文面が変わった場合は、実行例と似た非一致例を確認してから別の形式を追加する。

## 一般説明

詳細ルールに一致しない場合は、例外の種類に対して次の文を使う。修正方法を断定せず、確認する対象を示す。

| 例外 | 一般説明 |
| --- | --- |
| `SyntaxError` | 文法に関するエラーが発生しました。括弧、コロン、引用符などを確認してください。 |
| `IndentationError` | 行頭の空白を確認してください。 |
| `TabError` | インデントに使ったタブと空白を確認してください。 |
| `NameError` | 使った名前を確認してください。 |
| `UnboundLocalError` | 関数内で使った名前を確認してください。 |
| `AttributeError` | 属性やメソッドの名前を確認してください。 |
| `TypeError` | 型や引数に関するエラーが発生しました。 |
| `ValueError` | 値に関するエラーが発生しました。 |
| `IndexError` | 位置に関するエラーが発生しました。 |
| `KeyError` | キーに関するエラーが発生しました。 |
| `ZeroDivisionError` | 0で割る処理を確認してください。 |
| `ImportError` | 読み込む名前と実行環境を確認してください。 |
| `ModuleNotFoundError` | モジュール名と実行環境を確認してください。 |
| `FileNotFoundError` | ファイル名と保存先を確認してください。 |
| `RecursionError` | 再帰の終了条件を確認してください。 |
| `EOFError` | 入力の行数を確認してください。 |
| その他 | プログラムの実行中にエラーが発生しました。 |

`ModuleNotFoundError`、`TabError`、`IndentationError`、`UnboundLocalError`、`FileNotFoundError` は、それぞれ親の例外より先に判定する。
利用者のコードが `TypeError` などを自分で発生させ、Python標準のエラー本文に似せた場合は見分けられない。この限界があるため、詳細ルールは標準的な形式への厳密な一致に限定する。

## 受け入れ条件

- 上表の6例を、実際にPythonを実行した結果と代表的なエラー本文の両方で確認する。
- 詳細ルールはそれぞれ、一致する例と似ているが一致しない例をテストする。名前や値の抽出、長すぎる値、改行・制御文字を含む値も確認する。
- `"str" - 1`、引数個数の不一致、未知の型名、独自の `TypeError` 本文は `+` の説明にしない。
- 上表の例外では、詳細ルールに一致しないときに表の一般説明を表示する。親子関係がある例外は、より具体的な種類を優先する。
- `[0] + [1]` のように正常終了したコードには、エラー説明を出さない。
- 連鎖例外、構文エラー、ユーザーファイルとライブラリが混在するトレースバックで、原因と行番号の対応を確認する。
- stderrに注意事項だけがある正常終了、例外行のない異常終了、タイムアウト、起動失敗で、それぞれ適切な一般説明を確認する。
- 元のstderrを失わず、詳細設定で必要なときに読めることを確認する。

## 根拠

- [Python公式: 組み込み例外](https://docs.python.org/3/builtins/exceptions.html)には、例外の種類と、利用者のコードも組み込み例外を発生させられることが説明されている。
- [Python公式: traceback](https://docs.python.org/3/library/traceback.html)には、例外の連鎖と表示形式が説明されている。
